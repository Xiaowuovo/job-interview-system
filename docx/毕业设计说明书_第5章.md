# 第5章 系统实现

## 5.1 系统开发环境

本系统的开发在以下软硬件环境中完成。

**硬件环境**：开发机器配置为Intel Core i5处理器、16GB内存、512GB SSD存储，网络环境支持访问智谱AI外部API服务。

**软件环境**：
- 操作系统：Windows 10 / Windows 11
- JDK版本：OpenJDK 1.8（用于编译和运行SpringBoot应用）
- Maven版本：3.6.3（后端项目依赖管理和构建工具）
- Node.js版本：16.x LTS（前端开发服务器和npm包管理）
- IDE：IntelliJ IDEA 2023.x（后端开发）、Visual Studio Code（前端开发）
- 数据库：H2 Database（内嵌，开发阶段无需单独安装）；MySQL 8.0（生产环境）
- 浏览器：Google Chrome（开发和测试主用浏览器）
- 接口测试工具：Postman（API接口调试）

**项目结构**：
后端项目位于backend/目录，基于Maven管理，pom.xml中声明了spring-boot-starter-web、spring-boot-starter-data-jpa、h2、mysql-connector-java、lombok等核心依赖；前端项目位于frontend/目录，基于npm管理，package.json中声明了vue、vue-router、element-ui、axios、echarts、markdown-it等核心依赖。

系统通过start-system.bat批处理脚本实现一键启动，同时启动后端SpringBoot服务（端口8081）和前端Vue开发服务器（端口8080），开发体验友好。

## 5.2 用户登录注册模块功能实现

**注册功能实现**：前端Register.vue组件通过el-form和el-form-item结合rules属性配置了完整的表单验证规则。自定义验证器validateConfirmPassword用来检查"确认密码"是否和"密码"字段一致，通过callback(new Error('两次输入密码不一致'))的方式向用户反馈错误。表单验证通过后，调用this.$http.post('/users/register', this.form)向后端提交注册信息，成功后跳转到登录页。

后端UserController中的注册接口如下：

```java
@PostMapping("/register")
public Result<User> register(@RequestBody Map<String, String> params) {
    String username = params.get("username");
    String password = params.get("password");
    String email    = params.get("email");
    // 用户名和邮箱唯一性校验
    if (userRepository.findByUsername(username).isPresent()) {
        return Result.error("用户名已存在");
    }
    User user = new User();
    user.setUsername(username);
    // 密码加盐哈希处理
    String salt = UUID.randomUUID().toString().replace("-", "");
    user.setSalt(salt);
    user.setPassword(DigestUtils.md5Hex(password + salt));
    user.setEmail(email);
    user.setRole(User.Role.STUDENT);
    return Result.success(userRepository.save(user));
}
```

**登录功能实现**：登录接口通过username查询用户记录，取出salt后对输入密码进行相同的MD5+盐值哈希，与数据库中存储的哈希值比较。比较成功则构造返回体（排除password和salt字段），比较失败则返回错误响应。前端Login.vue接收到成功响应后，将用户信息序列化存入localStorage，然后通过this.$router.push('/home/dashboard')跳转到仪表盘页面。

**路由守卫实现**：在router/index.js中通过router.beforeEach实现全局路由守卫，核心逻辑如下：

```javascript
router.beforeEach((to, from, next) => {
  if (to.path === '/login' || to.path === '/register') {
    next(); return;
  }
  const userStr = localStorage.getItem('user');
  if (!userStr) { next('/login'); return; }
  const user = JSON.parse(userStr);
  if (!user || !user.id) {
    localStorage.removeItem('user');
    next('/login'); return;
  }
  // 教师端路由权限校验
  if (to.meta.requiresTeacher && user.role !== 'TEACHER') {
    next('/home/dashboard'); return;
  }
  next();
});
```

守卫代码简洁高效，覆盖了未登录拦截和角色权限校验两个核心场景，同时对localStorage中存储格式异常的情况做了try-catch防护，避免JSON解析失败导致的白屏。

**个人中心实现**：Profile.vue通过mounted钩子调用loadUserInfo()方法，分别请求/api/users/{id}获取最新用户信息、/api/reports/study/{id}获取学习统计摘要。编辑资料功能通过el-dialog弹窗实现，用户修改信息后提交PUT /api/users/{id}接口更新数据库，成功后同步更新localStorage中的用户信息缓存，保证界面显示与后端数据一致。修改密码时，后端需要同时验证旧密码的正确性，防止未授权的密码更改。

## 5.3 学生端功能实现

### 5.3.1 题库练习功能实现

**练习入口页面（Practice.vue）**：页面以卡片网格布局展示各技术分类（Java、前端、数据库、算法、系统设计），每张分类卡片显示该分类下的题目总数和难度分布。用户点击分类卡片后，通过this.$router.push('/home/test/' + category)跳转到对应分类的测试页面，category作为路由参数传入Test.vue。

**测试页面（Test.vue）**：组件通过this.$route.params.category获取当前练习分类，在用户确认题目数量后，调用this.$http.get('/questions/random?category=' + category + '&count=' + count)获取随机题目列表。测试进行中，使用currentIndex变量跟踪当前题目序号，answers数组的下标与题目列表一一对应，记录用户对每道题的选择结果。每道题目右上角的收藏按钮通过调用isFavorited(question.id)方法判断当前题目是否已收藏（通过本地缓存的favoritedIds Set实现），并以星形图标的填充/空心状态区分。

答题完成后点击"提交"，组件遍历answers数组，针对每道题的作答情况调用/questions/check接口完成判题，同时对错误答案调用/wrong-questions/add接口写入错题本，最后将本次测试总体数据提交到/test-records接口。测试结果展示区以题目列表的形式呈现每道题的判断结果，正确的题目以绿色勾标记，错误的题目以红色叉标记，点击展开可以查看正确答案和解析内容，帮助用户在练习完成后立即进行复盘。

### 5.3.2 AI模拟面试功能实现

**面试配置与启动（Interview.vue）**：Interview.vue组件的起始状态是一个配置表单，用户填写position（目标岗位）字段并选择interviewType（TECHNICAL/BEHAVIORAL/HR），确认后调用startInterview()方法，向POST /api/interview/start发送请求，成功后记录sessionId，切换到对话界面。

**对话界面**：对话界面以messages数组作为数据模型，数组中的每个元素包含role和content两个字段。页面通过v-for渲染消息列表，通过判断role的值为"AI"还是"USER"来决定气泡框出现在左侧还是右侧，并以不同的背景色区分双方消息，营造出接近即时通讯软件的视觉效果。每次用户发送消息时，先将用户消息即时追加到messages数组（让用户能立刻看到自己的发送内容），再调用/interview/chat接口。考虑到AI生成需要一定时间，接口调用期间显示"AI正在思考中..."的加载状态，避免用户以为页面卡顿。接口返回后将AI回复追加到messages数组，并自动将对话列表滚动到底部（通过$nextTick + scrollTop的方式实现），保证最新消息始终在可见区域。

**面试计时**：页面左侧显示面试计时器，通过setInterval每秒更新已用时间，以"分:秒"的格式展示，让用户能感知面试时长，避免单轮回答过长。

**结束面试与报告跳转**：点击"结束面试"按钮后调用/interview/end/{sessionId}接口，后端完成评分并返回更新后的InterviewSession数据，前端随即通过this.$router.push('/home/interview-report/' + sessionId)跳转到面试报告页面。

**面试报告（InterviewReport.vue）**：报告页面通过路由参数获取sessionId，调用GET /api/interview/session/{sessionId}加载面试数据，将对话记录从JSON字符串解析成数组后以对话气泡的形式重新渲染，让用户可以完整回顾本次面试的全程表现。综合评分以大号数字突出展示，AI评价文本以段落形式展示。

### 5.3.3 知识库功能实现

**知识点列表（Knowledge.vue）**：页面顶部提供三个筛选条件：分类下拉选择（el-select）、难度下拉选择和关键词搜索框（el-input）。筛选条件变化时调用searchKnowledge()方法，该方法调用loadKnowledgePoints()重新请求/api/knowledge接口，在参数中携带category、difficulty、keyword三个查询参数。后端KnowledgeController根据参数构造动态查询条件，返回过滤后的知识点列表。

知识点以el-col卡片网格形式展示，每张卡片显示知识点标题、分类、难度标签、重要度、浏览次数等信息，并在卡片底部展示用户已标记的学习进度标签（通过getStudyProgress(kp.id)方法从本地已加载的studyRecords数组中匹配）。

**知识点详情弹窗**：点击卡片后触发viewDetail(kp)方法，将currentKnowledge设为当前知识点对象，detailDialogVisible设为true，弹出el-dialog详情弹窗。同时并行发起两个请求：一是GET /api/favorites/check-type检查收藏状态，二是GET /api/knowledge/study/{userId}/{kpId}获取当前学习进度，两者都在then回调中更新组件的响应式数据，驱动页面重新渲染。

知识点正文通过以下代码完成Markdown渲染：
```javascript
renderMarkdown(content) {
  return md.render(content || '')
}
```
md是在组件外部初始化的MarkdownIt实例，render方法将Markdown文本转换为HTML字符串，通过v-html指令绑定到显示容器上。

**学习进度标记**：详情弹窗底部的三个级别按钮（了解/熟悉/掌握）共用setLevelAndSave(level)方法，该方法构造包含userId、knowledgePointId、progress（了解对应30、熟悉对应70、掌握对应100）、level的请求体，POST到/api/knowledge/study，成功后刷新学习记录并关闭弹窗。

### 5.3.4 错题本功能实现

**页面数据加载**：WrongQuestions.vue在mounted钩子中并行调用loadWrongQuestions()和loadAllQuestions()两个方法。前者从/api/wrong-questions/user/{userId}获取用户的错题记录列表；后者从/api/questions获取所有题目（或仅获取用户做过的题目），将题目数据建立以questionId为key的Map缓存（questionsMap），方便后续通过questionId快速取得题目的完整内容，而无需为每条错题单独发请求。

**表格展开行**：错题列表使用el-table的expand展开行功能，通过type="expand"的el-table-column实现。展开行内的插槽通过slot-scope="props"拿到当前行的错题数据，再通过props.row.questionId从questionsMap中取出题目内容，渲染到"题目内容"区域。这样的设计避免了在列表中一次性渲染所有题目内容，既节省了初始渲染的开销，又保证了展开后数据的完整性。

**笔记编辑功能**：点击"添加笔记"/"编辑笔记"按钮触发editNotes(row)方法，将currentEditingRow设为当前错题记录，editingNotes设为当前记录的notes字段内容（若为空则显示为空字符串），打开笔记编辑对话框（el-dialog内嵌el-input textarea）。用户编辑完成后点击保存，调用PUT /api/wrong-questions/{id}接口更新notes字段，成功后关闭对话框并刷新列表。

**标记已掌握**：markAsMastered(row)方法调用PUT /api/wrong-questions/{id}，将请求体中的isMastered字段设为true。后端同时更新reviewCount、lastReviewAt，并根据新的reviewCount值更新nextReviewAt。操作成功后列表中该条记录的掌握状态标签由"待复习"变为"已掌握"，"标记已掌握"按钮也随之消失（通过v-if="!props.row.isMastered"控制）。

**统计卡片**：页面顶部的四个统计卡片（错题总数、已掌握数、待复习数、平均错误次数）通过计算属性（computed）从已加载的wrongQuestions数组中动态计算得出，无需额外的接口请求。统计数据随着用户操作（标记已掌握、移除错题）实时更新，始终与列表状态保持一致。

### 5.3.5 学习报告功能实现

**数据聚合接口**：学习报告的核心数据由后端ReportController的GET /api/reports/study/{userId}接口提供，该接口接收period参数（week/month，默认为全部），在接口内部分别查询多个数据源并聚合：

- 从study_records表统计总学习时长和学习天数
- 从answer_records表统计总答题数、各分类答题数和正确率
- 从test_records表统计测试次数和平均得分
- 从interview_sessions表统计模拟面试次数和平均评分
- 从wrong_question_book表统计当前错题数
- 从question_favorites表统计收藏题目数

所有统计数据合并成一个Map<String, Object>返回给前端，减少了前端需要发起的请求次数。

**ECharts图表绑定**：StudyReport.vue页面在mounted钩子中先加载报告数据，在then回调中调用initCharts()方法初始化各ECharts实例。initCharts()的执行必须在DOM渲染完成之后（通过this.$nextTick保证），否则图表容器div的宽高尚未确定，ECharts无法正确计算布局。学习时长趋势折线图的x轴数据和y轴数据分别对应日期列表和每日学习分钟数，这部分数据由后端按天聚合后返回。各分类正确率的柱状图x轴为分类名称数组，y轴为各分类的正确率百分比，可以直观看出哪个技术方向是薄弱点。

时间维度的切换（周报/月报/累计）通过el-radio-group组件实现，切换事件触发loadReport()重新请求接口，接口携带不同的period参数，返回对应时间范围的统计数据，图表数据随之更新。

## 5.4 教师端功能实现

### 5.4.1 题目管理功能实现

**权限控制**：教师端页面的路由在router/index.js中配置了meta: { requiresTeacher: true }元信息，路由守卫在每次路由跳转时检查当前用户的role字段，非TEACHER角色的用户尝试访问这些路由时会被重定向到仪表盘页面，从根本上杜绝了权限越界的可能。

**题目列表与筛选（QuestionManage.vue）**：教师端题目管理页面加载时，请求GET /api/questions并在前端按createdBy字段过滤出当前教师创建的题目（也可由后端接口直接支持按createdBy过滤，减少无效数据传输）。页面顶部提供分类和难度的筛选下拉框，以及关键词搜索框，所有筛选条件通过computed属性（filteredQuestions）过滤列表数据，响应速度快、无需额外请求。

**新增题目对话框**：点击"新增题目"按钮打开el-dialog，内含一个多字段的el-form，字段包括题目标题、题目内容（el-input textarea）、题目类型（el-select）、难度（el-select）、分类（el-select）、选项A-D（题目类型为选择题时显示，v-if控制）、正确答案、解析说明和标签。表单校验要求题目内容和题目类型为必填项。提交时调用POST /api/questions，创建成功后关闭对话框并刷新列表，弹出成功提示。

**编辑与删除**：列表中每道题目行末提供编辑和删除操作按钮。编辑时将当前行数据赋值给editForm，打开同一个对话框（通过isEdit标志区分新增和编辑模式），提交调用PUT /api/questions/{id}。删除时通过this.$confirm弹出二次确认对话框，用户确认后调用DELETE /api/questions/{id}，成功后从本地列表中移除该条记录，无需重新加载全量数据。

### 5.4.2 教程与知识点管理功能实现

**教程管理（TutorialManage.vue）**：教程管理页面的整体交互模式与题目管理类似，以列表+对话框的形式实现增删改操作。新建教程时填写标题、分类（基础指导/技术面试/行为面试）和内容，提交到POST /api/tutorials创建记录。列表中展示各教程的标题、分类、浏览次数和创建时间，支持按分类筛选和关键词搜索。值得一提的是，教程内容的编辑采用el-input的textarea模式，支持用户直接输入富文本内容，前端在展示时通过换行符转换（content.replace(/\n/g, '<br>')）处理段落，实现基础的格式呈现。

**知识点管理（KnowledgeManage.vue）**：知识点管理页面支持Markdown格式内容的录入，教师可以在内容文本框中直接输入Markdown语法，系统在学生端的知识库详情页进行渲染展示。表单中的难度选择（简单/中等/困难）和重要度评分（1-5，通过el-rate或el-input-number实现）字段，帮助教师为知识点设置合理的学习优先级引导。提交数据到POST /api/knowledge创建知识点，后端同时更新该分类下的知识点数量统计，教师工作台的统计数字实时反映最新的内容数据。

**教师工作台（TeacherDashboard.vue）**：工作台页面以统计卡片的形式展示当前教师的内容产出概况，数据来源于并行的多个接口请求（题目数、教程数、课程数、知识点数）。卡片点击后跳转到对应的管理页面，使工作台同时具备数据概览和导航功能。

## 5.5 本章小结

本章按照功能模块的维度，系统地描述了就业面试辅助系统各核心功能的具体实现方式。在公共基础层面，用户认证模块通过密码加盐哈希保障了账号安全，路由守卫机制实现了前端的访问控制。在学生端，题库练习模块通过随机抽题、自动判题和错题自动归档形成了完整的刷题闭环；AI模拟面试模块通过接入智谱AI大语言模型，实现了多类型面试场景的沉浸式模拟，并自动生成面试报告；知识库模块结合Markdown渲染和三级学习进度标记，提供了结构化的知识管理体验；错题本模块通过艾宾浩斯复习节点设计帮助用户突破记忆瓶颈；学习报告模块通过ECharts多维图表让用户直观感知自己的备考进展。在教师端，题目管理、教程管理和知识点管理三个模块共同构成了系统内容层的运营工具，保障了题库和知识库内容的持续供给。
