# 第3章 系统需求分析

## 3.1 可行性分析

在正式启动系统开发之前，有必要从技术可行性、经济可行性和操作可行性三个维度评估本项目的落地条件。

**技术可行性方面**，本系统所采用的技术栈均已经过大规模工程项目的充分验证，没有引入尚处于实验阶段的技术组件。SpringBoot和Vue.js都是业界广泛使用的成熟框架，开发团队能够在较短时间内上手并完成开发工作；Spring Data JPA简化了数据访问层的开发量，H2内嵌数据库使开发阶段无需单独安装数据库服务，降低了环境搭建成本；AI能力方面，智谱AI提供了稳定的API服务接口和详细的接入文档，GLM-4-Flash模型对中文的理解和生成质量能够满足模拟面试场景的需求，且提供了每天百万Token的免费额度，开发阶段不会产生额外成本。综合来看，本项目在技术上完全可行。

**经济可行性方面**，系统所使用的核心技术框架和组件均为开源免费软件，无需支付商业授权费用。开发阶段使用H2内嵌数据库，生产环境切换到MySQL 8.0，两者的迁移成本很低。AI服务在开发阶段使用智谱AI的免费配额，正式上线后所需的API调用费用在合理范围内可控。从整体来看，项目的技术成本相当有限，主要投入是开发人员的时间成本，经济上具备可行性。

**操作可行性方面**，系统面向的主要用户是在校大学生和应届毕业生，这类群体的计算机操作能力普遍较强，能够熟练使用浏览器访问Web应用。系统的交互设计遵循主流Web产品的使用习惯，导航结构清晰，操作路径简短，对用户的学习成本要求极低。对于教师用户，系统提供了可视化的内容管理界面，无需了解任何技术背景即可完成题目和教程的增删改操作。

## 3.2 系统需求概述

本系统的使用者分为两类角色：学生用户和教师用户。学生用户是系统的主要服务对象，他们来到系统的目的是系统地准备就业面试，其核心需求包括刷题练习、AI模拟面试、学习资料查阅、错题整理和学习进度追踪；教师用户是系统内容的提供者，他们的主要需求是能够方便地管理题目、教程和知识点等内容资源。

从更宏观的视角看，系统需要解决"学什么、怎么练、练得怎么样"这三个核心问题。"学什么"对应知识库和教程模块，为用户提供系统化的知识体系；"怎么练"对应题库练习和AI模拟面试模块，为用户提供多维度的实战训练手段；"练得怎么样"对应学习报告和错题本模块，通过数据反馈帮助用户认识自身现状，指导下一步的复习重点。

系统还需要在用户管理层面做好基础工作，包括用户注册、登录、个人资料管理，以及角色权限控制——不同角色的用户只能看到和操作与自己权限相符的功能模块。

## 3.3 系统功能性需求分析

### 3.3.1 学生端模块需求分析

**（1）用户注册与登录**

新用户首次使用系统时，需要通过注册页面填写用户名、密码、邮箱等基本信息完成账号创建。注册过程中，系统需要对输入数据进行校验：用户名不能重复、密码长度需满足最低要求、邮箱格式需符合规范。注册成功后，用户可以使用用户名和密码登录系统，登录成功后服务端将用户信息返回给前端，前端将其存储在localStorage中，作为后续页面认证和数据请求的凭据。

用户在登录后可以访问个人中心页面，查看和修改自己的昵称、邮箱、手机号、目标岗位等个人资料，也可以在此修改账号密码。个人中心还展示用户的学习统计数据（累计学习天数、完成题目数量、模拟面试次数等）和最近的活动记录，帮助用户感知自己的学习投入情况。

**（2）仪表盘（Dashboard）**

用户登录后进入的默认页面是仪表盘，它的定位是一个信息聚合的概览页面。仪表盘需要展示几项关键的学习状态指标：今日已完成的练习题数、本周的学习天数、错题本中待复习的题目数量、收藏夹题目数。同时，还需要显示最近一次AI模拟面试的评分情况，以及学习时长的趋势折线图。

仪表盘页面还需要提供快速入口，让用户一键跳转到常用功能模块，比如直接开始今日练习、进入AI模拟面试、查看待复习错题等，减少用户在各页面间跳转的操作步骤。系统还会在仪表盘展示每日推荐题目，根据用户的薄弱分类智能推荐，强化对薄弱知识点的关注。

**（3）面试教程**

面试教程模块为用户提供系统化的面试知识资料，内容涵盖基础指导（简历撰写技巧、面试礼仪、自我介绍技巧等）、技术面试技巧（算法思路分析、系统设计方法论等）和行为面试技巧（STAR法则讲解、常见行为面试题分析等）三大类。

用户可以在教程列表页按分类标签筛选感兴趣的内容，也可以通过搜索框关键词检索教程标题。点击某篇教程后进入详情页，以Markdown渲染的方式展示富文本内容，包括文字说明、代码块和有序列表等格式。每篇教程都有浏览次数统计，帮助用户识别热门内容。教程列表中的每张卡片都提供了收藏按钮，用户可以将感兴趣的教程加入收藏夹，方便后续回顾。

**（4）题库练习**

题库练习是系统的核心功能之一，用户通过它进行刷题训练。首先，用户在练习入口页面选择要练习的技术分类，可选分类包括Java、前端、数据库、算法、系统设计等。选定分类后，系统跳转到测试页面，从该分类下随机抽取若干题目（默认10题，用户可以在5到20题之间自定义数量）组成本次练习集。

测试进行中，页面顶部显示当前题目序号和倒计时，用户依次作答每道题，支持上一题/下一题的跳转导航。每道题目顶部提供收藏按钮，用户可以随时将感兴趣的题目加入收藏夹。答完所有题目后，用户提交本次练习，系统计算总分并展示答题详情，每道题都会显示用户的作答情况、正确答案以及详细的解析说明。对于答错的题目，系统自动将其记录到错题本中，并基于艾宾浩斯遗忘曲线安排第一次复习时间。

**（5）AI模拟面试**

AI模拟面试模块是本系统最具特色的功能，允许用户在接近真实的对话场景中演练面试。用户首先填写目标岗位名称（如"Java后端开发工程师"），然后选择面试类型，包括：技术面试（侧重技术能力、编程思路、项目经验的考查）、行为面试（侧重过往经历、团队协作、应对挑战的经验）和HR面试（侧重职业规划、岗位匹配度和薪资期望等话题）三种类型。

面试开始后，AI面试官根据岗位和面试类型自动生成个性化的开场白，此后进入多轮对话环节。用户在输入框中输入自己的回答，系统将当前对话上下文发送给智谱AI的GLM模型，模型依据面试官角色设定生成下一个问题或追问，页面以气泡对话框的形式呈现完整的对话历史。

面试结束后，系统对本次面试进行评分并生成面试报告，报告内容包括本次面试的综合评分、具体的表现分析和改进建议。用户可以在"成绩记录"页面查看历次面试的详情，追踪自己面试表现的成长轨迹。面试过程中会显示计时器，帮助用户控制作答节奏。

**（6）知识库**

知识库模块提供了结构化的面试知识体系，按照技术分类组织知识点，每个知识点包含标题、所属分类、难度级别（简单/中等/困难）、重要度评分以及详细的知识内容。知识内容以Markdown格式存储，在前端渲染后支持代码块高亮、有序列表等富文本格式，方便展示带有代码示例的技术知识。

用户可以通过分类下拉筛选、难度筛选和关键词搜索三种方式定位感兴趣的知识点。点击知识点卡片后弹出详情对话框，展示完整内容。在详情页底部，用户可以点击"了解"、"熟悉"、"掌握"三个按钮之一来标记当前知识点的学习进度，点击后系统自动保存进度记录并关闭弹窗，操作便捷。知识点列表卡片上会显示用户已标记的学习进度标签，一目了然。详情页头部还提供收藏按钮，用户可以将重要知识点加入收藏夹，方便后续快速回顾。

**（7）错题本**

错题本模块负责收集和管理用户在练习中答错的题目，是系统辅助用户攻克薄弱知识点的重要工具。页面顶部展示四个统计卡片，分别显示错题总数、已掌握题目数、待复习题目数和平均错误次数，给用户一个整体感知。

错题列表以可展开的表格形式呈现，每行显示题目的分类、难度、错误次数、最近错误时间和掌握状态等信息，展开行后可以看到题目的详细内容。用户可以针对每道错题执行以下操作：添加或编辑个人学习笔记（记录自己的理解和易错点分析）、将题目标记为已掌握（标记后从待复习列表中移除）、从错题本中移除该题目。页面顶部提供按分类和难度的筛选功能，以及关键词搜索，方便用户在大量错题中快速定位目标。

**（8）收藏夹**

收藏夹模块统一管理用户在各页面收藏的内容，支持题目、知识点、教程三种类型的收藏数据。页面以表格列表展示所有收藏项，用户可以通过类型标签筛选仅查看某一类型的内容。每条收藏记录显示内容的标题、分类和收藏时间。用户可以直接在收藏夹页面查看收藏内容的详情，也可以为每条收藏添加个人学习笔记，或者随时取消收藏。

**（9）学习报告**

学习报告模块通过多维度的数据图表展示用户的学习状况，帮助用户了解自己的备考进展，找出需要加强的方向。报告页面分周报、月报和累计三个时间维度，用户可以自由切换。核心指标包括：总学习时长（小时）、学习天数、每日平均学习时长；题目练习维度展示总答题数、正确率、各分类的答题准确率柱状图；模拟面试维度展示完成场次和平均评分；知识库学习维度展示已学知识点数量和各掌握级别的分布饼图。通过ECharts图表，这些数据以直观的可视化形式呈现，方便用户对自己的备考状态做出判断。

### 3.3.2 教师端模块需求分析

**（1）教师工作台**

教师登录后，在左侧导航栏的"教师管理"分区中可以访问教师端专属功能，首先进入的是教师工作台（TeacherDashboard）页面。工作台以概览形式展示该教师名下的内容统计，包括已发布的题目数量、教程数量、课程数量和知识点数量，以及最近的内容更新记录。工作台帮助教师快速掌握自己在平台上的内容运营情况，并从这里快速跳转到各管理子模块。

**（2）题目管理**

题目管理模块（QuestionManage）是教师端最核心的功能之一，支持对题目的全生命周期管理。教师可以在此新建题目，填写题目内容、题目类型（单选题、多选题、编程题、简答题、系统设计题五种类型之一）、所属分类（Java、前端、数据库、算法等）、难度级别、选项内容（选择题类型）、正确答案和解析说明，还可以为题目添加标签以便于分类检索。

在题目列表中，教师可以搜索自己已发布的题目，支持按分类和难度筛选；点击某道题目可以进入编辑页面修改内容；不再需要的题目可以删除。系统显示每道题目的浏览次数和答对率统计，帮助教师了解哪些题目学生访问多、哪些题目的通过率偏低，作为后续优化题目内容的参考依据。

**（3）教程管理**

教程管理模块（TutorialManage）让教师能够创建和维护面试教程内容。新建教程时需要填写教程标题、所属分类（基础指导、技术面试、行为面试）和正文内容，内容支持自由文本格式（系统在前端展示时会自动进行格式处理）。教师可以在教程列表中查看自己已发布的所有教程，并对内容进行编辑或删除操作。教程的浏览次数实时统计，帮助教师了解各篇内容的受欢迎程度。

**（4）课程管理**

课程管理模块（CourseManage）支持教师创建结构化的课程内容，将相关的学习资料组织成具有章节体系的课程形式。教师可以为课程设置标题、描述、分类标签，以及设定课程的难度定位。课程创建后对学生端可见，学生可以选择完整学习某门课程。系统为教师提供课程列表的管理界面，支持课程的编辑、上下架操作，方便内容的持续更新和维护。

**（5）知识点管理**

知识点管理模块（KnowledgeManage）允许教师为知识库贡献内容。教师可以新建知识点，填写标题、所属分类、难度级别、重要度（1到5星）、正文内容（支持Markdown格式）和标签。知识点内容支持Markdown语法，方便编写包含代码示例的技术知识。教师可以在管理列表中对已发布的知识点进行编辑和删除，系统显示每个知识点的浏览次数，作为内容质量评估的参考。

## 3.4 系统非功能性需求分析

除了各功能模块的具体需求之外，系统还需要满足一系列非功能性要求，这些要求虽然不直接体现在某个具体的功能点上，但对用户体验和系统长期运行的稳定性有着直接影响。

**性能需求方面**，系统的接口响应时间需要控制在合理范围内。对于普通的数据查询接口，响应时间应当在500毫秒以内；涉及AI生成的接口（如模拟面试对话）受限于第三方服务调用，响应时间允许稍长，但也不应超过10秒，否则会明显影响用户的对话体验。页面初次加载的时间需要在3秒以内完成，后续通过路由懒加载（Vue Router的按需import组件）减少非当前页面的资源请求，提升页面切换的流畅度。

**可用性需求方面**，系统界面需要具备良好的可访问性和一致性。所有表单操作都需要有即时的反馈提示（成功提示、失败提示、加载状态），避免用户因为不知道操作是否生效而反复点击。错误信息需要以用户易懂的语言表达，而不是直接暴露技术性错误堆栈。在网络状况不佳导致请求失败时，系统应显示明确的错误提示，而不是白屏或无响应。

**安全性需求方面**，用户密码在存储时需要经过加盐哈希处理，不能以明文形式保存在数据库中。前端路由守卫（router.beforeEach）保证未登录用户无法直接访问业务页面，教师端路由设有角色验证，防止普通学生用户访问管理功能。跨域请求通过后端的CorsConfig配置进行控制，避免非法来源的请求访问API。

**可维护性需求方面**，代码结构应遵循分层架构原则，后端按照Controller、Service、Repository三层分离，各层职责清晰，便于后续的功能扩展和缺陷定位。前端按照功能页面拆分为独立的.vue组件，公共逻辑封装在utils目录下的工具类中，减少代码重复。数据库的DDL变更通过JPA的ddl-auto机制自动处理，无需手动维护SQL脚本，降低了版本迭代中的数据库维护成本。

**兼容性需求方面**，前端应用需要支持主流浏览器（Chrome、Firefox、Safari、Edge的较新版本），对于分辨率在1280px以上的桌面端屏幕提供良好的布局表现。系统当前主要面向桌面端用户，但界面的响应式布局设计为未来支持移动端访问预留了基础。

## 3.5 本章小结

本章从可行性分析入手，分别从技术、经济和操作三个维度验证了项目的落地条件，结论是整体可行。随后，对系统的两类用户角色（学生和教师）各自的功能需求进行了系统性梳理，学生端覆盖了注册登录、仪表盘、教程学习、题库练习、AI模拟面试、知识库、错题本、收藏夹、学习报告等核心功能，教师端涵盖了工作台、题目管理、教程管理、课程管理和知识点管理五个子模块。最后，从性能、可用性、安全性、可维护性和兼容性五个维度说明了系统的非功能性需求。这些需求分析的结果将直接指导第4章的系统设计工作。
